# Implementation note: The cutoff is an admissible bound

- Lean name: `ZInQ.Size.admissible_T`.
- Draft:
  ```lean
  theorem admissible_T (hCAT : CatalogueBound) : Admissible (Syntax.T + 1) Syntax.library
  ```
- Proof: `T ≥ D` from `T_eq` (`Nat.le_mul_of_pos_left`, `Nat.le_self_pow` with positive
  exponent); `D > 2^(2^8008) > 2^69` etc. Each field of `Admissible` from
  `template_consts_small` / `template_constructor_exprs`, then the value lemmas:
  `FixedExpr.val (.ref .ell) = ell < 2^(2^2063) < D`; psi indices via `cstar_lt` and
  `|c_3| < 10^3181317 < 2^(2^24)`; the latter must come from the natural-circuit statistics
  (the article states that `c_3` has 3181317 decimal digits; make sure its Lean statement
  includes `c_3 < 10 ^ 3181317`, not only distinctness: see that article's note) or from a
  symbolic bound on the compiler's program encoding.
- Mathlib: `Nat.le_self_pow`, `Nat.pow_lt_pow_right`, `Nat.lt_pow_self`.
- Finite computation: no (symbolic; `10^3181317 < 2^(2^24)` can be proved as
  `10^3181317 < 16^3181317 = 2^12725268 < 2^16777216` without evaluation).
- Upstream reuse: none.
- Difficulty: low-medium (~80 lines).

Shared design (majorant notes): `Maj B h P : Prop := if h = 0 then P.totalDegree ≤ 1 ∧ l1 P ≤ 1
else P.totalDegree ≤ B ^ (8 * h) ∧ l1 P ≤ 2 ^ B ^ (8 * h)` (helper def in `ZInQKernel/Size/Majorant.lean`).
Heights are computed on the syntax chapter's node lists (`ZInQ.Syntax.Template.nodes`, produced by
`Prog.dag`), so they depend only on syntax, never on the values of fixed expressions.
