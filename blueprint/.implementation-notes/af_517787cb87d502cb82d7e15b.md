# Implementation note: The relation Close

- Lean name: `ZInQ.Assembly.close_rel_iff`.
- Draft:
  ```lean
  theorem close_rel_iff (hyps) (N K : Fin 5 → ℚ) (t : ℚ) :
      RelT Syntax.closeRecipe (Fin.append (Fin.append N K) ![t]) ↔
        ∃ n κ a l : ℤ, N = iota n ∧ K = iota κ ∧ Prec n κ a l (n * a) ∧
          |t - rWin a (n * a)| < epsWin l
  ```
- Input C in its interface form (compiler chapters): the rational translation gives
  `RelT Syntax.precisionRecipe (flatten E) ↔ ∃ c : Fin 5 → ℕ, (∀ i, E i = iota (c i)) ∧
  ∃ z : Fin 1305806 → ℕ, C (c, z) = 0` (needs M, hence `hyps`), the natural semantics gives
  `(∃ z, C (c, z) = 0) ↔ acceptsNaturals c`, and `accepts_iff_Prec` (precision-acceptance note)
  gives `acceptsNaturals c ↔ Prec (dec (c 0)) … (dec (c 4))`. Combine them into a local
  `precision_rel_iff` and then prove `close_rel_iff` from it.

## After the dedupe

- The precision predicate is now the compiler chapter's precision relation, read at signed
  encodings: `Prec n κ a l j := accepts (enc n) (enc κ) (enc a) (enc l) (enc j)` (a local
  abbreviation, not a separate definition). The deleted bridge `accepts_iff_Prec` is replaced by
  `dec ∘ enc = id` (signed-encoding bijection), and admissibility is part of `accepts`.
- From the deleted `compiler/translation/precision-decision.md`: the local lemma
  `precision_rel_iff : RelT precisionRecipe (flatten E) ↔ ∃ c, (∀ i, E i = iota (c i)) ∧ accepts c`
  (rational translation item 1, then (C.4)) is the coordination point between the compiler and
  assembly chapters; it needs M, hence the hypotheses of the multiplication template.
