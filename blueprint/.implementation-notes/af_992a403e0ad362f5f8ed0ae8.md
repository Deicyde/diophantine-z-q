# Implementation note: The template library

- Lean names: `ZInQ.Syntax.library : List Template`, `ZInQ.Syntax.libraryPolys`,
  `ZInQ.Syntax.integerConstant : Fin 5 → ℤ`.
- Draft: `library := [memberTemplate, rawAddTemplate, ..., valueExceptionsTemplate] ++
  (List.finRange 5).map scalarConstantTemplate`. Calls inside templates refer to library
  indices (as in the JSON) so `Template.denote` can fold over the list. Pin the
  constant table instead of computing it: `integerConstant := ![4, 2, 3, c₃, 1399]` with `c₃`
  the compiler chapter's program literal (a named definition, never unfolded), and let the
  translation look up each nontrivial constant's index in this table. Computing the table
  by running the translation (`(translateAll natCircuit).constants`) would make `library`,
  and every kernel computation that touches it (for example the witness-count check), depend
  on evaluating the 293,620-node precision circuit. With the pinned table, the natural
  circuit statistics leaf carries the obligation that these five values are exactly the
  nontrivial constants met, in order of first occurrence, and pairwise distinct.
- Mathlib: none.
- Upstream reuse: none.
- Finite computation: no (the counts are the template witness-count check).
- Difficulty: low.

Shared design (all syntax notes): namespace `ZInQ.Syntax`, files under
`ZInQKernel/Syntax/`. Polynomials are `MvPolynomial ℕ ℤ`; evaluation over `ℚ` is
`MvPolynomial.eval₂ (Int.castRingHom ℚ) x`. Templates are written once as programs of a
small deep-embedded construction language `Prog` (free monad over: fresh variable, fresh
block call, rational constant, node operations, formula connectives) with three
interpreters: `Prog.dag` (hash-consed node list, mirrors the JS builder byte for byte, used
for heights and the cross-check), `Prog.formula` (readable `Formula` term, used for
semantics) and `Prog.count` (allocation counter only, cheap to evaluate in the kernel).
Fixed integer expressions stay symbolic (`FixedExpr` syntax, noncomputable `val`); no proof
ever evaluates `c_*`, `ell`, `T`, `D`, `Q` or the program literal `c_3`.
