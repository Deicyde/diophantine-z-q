# Implementation note: Semantics of the five-input specialization

- Lean name: `ZInQ.Machine.specialization_iff`.
- Draft:
  ```lean
  theorem specialization_iff (H : MvPolynomial ℕ ℤ) (V : ℕ) (hV : 2 ≤ V)
      (hvars : ∀ i ∈ H.vars, i < V) (e₀ : ℕ) (c : Fin 5 → ℕ) :
      (∃ z : Fin (V + 2) → ℕ, MvPolynomial.eval (natAssign c z) (specPoly H e₀) = 0) ↔
      (∃ v : Fin (V - 2) → ℕ, MvPolynomial.eval (headAssign e₀ (encode5 c) v) H = 0)
  ```
- Proof: `MvPolynomial.eval₂Hom_bind₁` for the shifted copy of `H`; sum of squares of integers;
  `pairing_chain_iff`.
- Mathlib: `MvPolynomial.vars`, `MvPolynomial.eval_eq_eval_mv_eval'` not needed;
  `Finset.sum_eq_zero_iff_of_nonneg`, `sq_nonneg`, `pow_eq_zero_iff`.
- Upstream reuse: `ZInQ.CantorDecoder.pairing_equation_iff`.
- FINITE COMPUTATION: no.
- Difficulty: low (~100 lines).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
