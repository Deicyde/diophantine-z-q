# Implementation note: Correctness of the wrapper

- Lean name: `ZInQ.Machine.wrapper_halts_iff`.
- Draft:
  ```lean
  theorem wrapper_halts_iff (prog : Prog) (hprog : prog.FinalHaltForm) (N : ℕ) (hN : 5 ≤ N)
      (hreg : prog.regBound ≤ N) (x : ℕ) :
      (wrapper prog).Halts [x] ↔ prog.Halts (decode5List x)
  ```
- Proof: prefix lemma (finite run to `(ℓ, R')` via `ZInQ.CantorDecoder.pair_loop`/`decode`
  invariants), relocation lemma (`step (prefix ++ relocate ℓ prog) ⟨p + ℓ, R⟩ = (step prog ⟨p, R⟩).map shift`),
  `StateTransition.tr_eval` both ways.
- Mathlib: `StateTransition.tr_eval`, `StateTransition.tr_eval_rev`, `List.getElem?_append_right`.
- Upstream reuse: `ZInQ.CantorDecoder.decode5_encode5`.
- FINITE COMPUTATION: no.
- Difficulty: medium (~200 lines).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
