# The canonical height of multiples of P0 (generator-height)

- Lean name: `ZInQ.Mult.canonHeightE`, `ZInQ.Mult.canonHeightE_zsmul_genP0`,
  `ZInQ.Mult.two_canonHeight_genP0_gt_one`, `ZInQ.Mult.two_canonHeightE_le`.
- Draft:
  ```lean
  noncomputable def canonHeightE (Q : genCurve.toAffine.Point) : ℝ := canonHeightC (theta Q)
  theorem canonHeightE_zsmul_genP0 (n : ℤ) : canonHeightE (n • genP0) = n^2 * canonHeightE genP0
  theorem two_canonHeight_genP0_gt_one : 1 < 2 * canonHeightE genP0
  ```
- Reuse: model chapter canonical-height, canonical-height-quadratic, canonical-height-bounds,
  height-of-2r, point-r-certificate, coordinate-change (`theta` as an `AddMonoidHom`/`AddEquiv`).
  Upstream `ZInQ.ModelCoordinateIdentities.scale_back` gives `theta⁻¹ (2R) = P0` coordinates.
- FINITE COMPUTATION: no (consumes height-constants). Difficulty: easy (~80 lines).

Shared design (multiplication chapter): namespace `ZInQ.Mult`, files under
`ZInQKernel/Multiplication/`. Points are `genCurve.toAffine.Point` over `K0 = QuadraticAlgebra ℚ 2 0`;
codes are `ZInQ.iota`; template relations are `ZInQ.Syntax.Rel`. Valuations on `K0` at a prime
`𝔭 : IsDedekindDomain.HeightOneSpectrum Zs` (with `Zs` the model chapter's `ℤ[√2]`) are taken as
`ℤ∪{∞}`-valued via `IsDedekindDomain.HeightOneSpectrum.valuation K0 𝔭` (multiplicative, `ℤᵐ⁰`);
a thin wrapper `ZInQ.Mult.vP 𝔭 : K0 → WithTop ℤ` is recommended. The completion is
`𝔭.adicCompletion K0`. The constants `c_*`, `ℓ_0`, `A_ht`, `T` are the syntax chapter's symbolic
`FixedExpr` values and are never evaluated (no `decide`/`norm_num` on them).
