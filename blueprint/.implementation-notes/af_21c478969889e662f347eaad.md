# Implementation note: Norm zero implies zero

- Lean name: none new if Mathlib's lemma applies: `QuadraticAlgebra.norm_eq_zero_iff_eq_zero`
  (checked: needs `[Fact (∀ r : K, r ^ 2 ≠ a + b * r)]`; for `K0 = QuadraticAlgebra ℚ 2 0` this is
  `∀ r : ℚ, r ^ 2 ≠ 2`, derivable from `ZInQ.not_isSquare_two_rat` in
  `ZInQKernel/Hypotheses/MordellWeil.lean`). Provide the instance as
  `ZInQ.Machine.fact_sq_ne_two` and the integer-pair form `ZInQ.Machine.intPair_norm_eq_zero`
  (`a ^ 2 - 2 * b ^ 2 = 0 → a = 0 ∧ b = 0` for `a b : ℤ`), which is what the register program
  tests.
- Mathlib: `QuadraticAlgebra.norm_eq_zero_iff_eq_zero`, `irrational_sqrt_two` (checked).
- Upstream reuse: none.
- FINITE COMPUTATION: no.
- Difficulty: trivial (~20 lines).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
