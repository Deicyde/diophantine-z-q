# Implementation note: Node statistics of the compiled circuits

- Lean names: `ZInQ.Compiler.Universal.haltingCircuit_nodeStats`,
  `precisionCircuit_nodeStats`, `powerTemplate_nodeStats` (share with the syntax chapter's
  `precisionCircuit_shape`, which states the same facts for $\mathcal N$).
- FINITE COMPUTATION. Decidable form:
  ```lean
  theorem haltingCircuit_nodeStats :
      haltingCircuit.nodes.length = 293568 ∧ countKind .var haltingCircuit = 54049 ∧
      countKind .add haltingCircuit = 125307 ∧ countKind .mul haltingCircuit = 98361 ∧
      countKind .call haltingCircuit = 15845 ∧ constList haltingCircuit = [0, 1, 2, 4, 1399, -1]
  ```
  Item 2 then follows from the definition of `specialize` (the appended part is a literal of
  52 nodes) without new computation, and `c3 ∉ {0,1,-1,2,4,1399}` from `c3_gt`.
- Size: 293,568 nodes built by the hash-consing interpreter from a 1,399-instruction
  program. Running the hash-consing builder inside the kernel is likely too slow for
  `decide` (each node needs a map lookup); routes: (a) milestone 1: `native_decide` (or an
  external check: the JS compiler with the hierarchical override reproduces the saved
  293,568 nodes from the recovered program, as verified while writing this chapter);
  (b) kernel: make the `dag` interpreter's map a `Nat`-keyed trie and certify with
  `Eq.refl true` on a Boolean checker; (c) symbolic: prove `countKind` of the packed
  construction's node list as a function of the program (explicit sharing analysis of
  constant subterms such as `K*F`, `Q+4`, `Q^2` with `Q = 2`), then evaluate on the
  interpreter's shape. Item 3 (474 nodes) is cheap by `decide`.
- Mathlib: `List.countP`.
- Upstream reuse: none.
- Difficulty: low with `native_decide`; high for the kernel routes.
