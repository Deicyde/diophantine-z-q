# Implementation note: The five-input specialization

- Lean names: `ZInQ.Machine.specPoly (H : MvPolynomial ℕ ℤ) (e₀ : ℕ) : MvPolynomial ℕ ℤ`,
  `ZInQ.Machine.specCircuit (N : Syntax.NatCircuit) (e₀ : ℕ) : Syntax.NatCircuit`,
  `ZInQ.Machine.specCircuit_poly : (specCircuit N e₀).poly P = specPoly (N.poly P) e₀`.
- Draft:
  ```lean
  noncomputable def specPoly (H : MvPolynomial ℕ ℤ) (e₀ : ℕ) : MvPolynomial ℕ ℤ :=
    (MvPolynomial.bind₁ (fun i => if i = 0 then C (e₀ : ℤ) else if i = 1 then X 5 else X (i + 7)) H) ^ 2 +
    ∑ i : Fin 4, (2 * T i - ((X i + T (i+1)) * (X i + T (i+1) + 1) + 2 * T (i+1))) ^ 2
  ```
  with `T 0..3 = X 5..X 8`, `T 4 = X 4`. The circuit version mirrors the node layout of the
  saved circuit (node 0 `const e₀`, node 1 `var 5`, shifted old nodes, five input nodes, three
  pairing variable nodes, constants `1, 2, -1`, the pairing nodes, squares and sums), which the
  cross-check compares with `precision-natural-polynomial.json`.
- The natural chapter defines the natural precision circuit as
  `specCircuit universalHaltingCircuit c3` (coordination point).
- Mathlib: `MvPolynomial.bind₁`, `MvPolynomial.eval₂Hom_bind₁` (checked).
- Upstream reuse: none.
- FINITE COMPUTATION: no.
- Difficulty: low-medium (~120 lines including the circuit-level equality).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
