# Implementation note: Comparison with the towers

- Lean name: `ZInQ.Size.tower_bounds`.
- Draft:
  ```lean
  theorem tower_bounds (T : ℕ) (hT : T < 2 ^ 2 ^ 2 ^ 9013) :
      (T + 1) ^ 2048 < hyperoperation 4 2 7 ∧ 2 ^ (T + 1) ^ 2048 < hyperoperation 4 2 8
  ```
- Upstream reuse (exact): `ZInQ.NumericalTowerBounds.degree_bound_of_cutoff_bound`,
  `coefficient_bound_of_cutoff_bound`, `triplePower_9014_lt_tower_seven`,
  `quadruplePower_9014_lt_tower_eight` (lean/ZInQ/NumericalTowerBounds.lean), all public and
  sorry-free; `triplePower a = 2 ^ 2 ^ 2 ^ a` by `rfl`. The proof is two `lt_trans`.
- Mathlib: `hyperoperation` (Mathlib/Data/Nat/Hyperoperation.lean), via upstream's `tower_succ`,
  `tower_four`.
- Finite computation: only `hyperoperation 4 2 4 = 65536` (upstream `tower_four`, by `decide`).
- Difficulty: trivial given upstream.

Shared design (majorant notes): `Maj B h P : Prop := if h = 0 then P.totalDegree ≤ 1 ∧ l1 P ≤ 1
else P.totalDegree ≤ B ^ (8 * h) ∧ l1 P ≤ 2 ^ B ^ (8 * h)` (helper def in `ZInQKernel/Size/Majorant.lean`).
Heights are computed on the syntax chapter's node lists (`ZInQ.Syntax.Template.nodes`, produced by
`Prog.dag`), so they depend only on syntax, never on the values of fixed expressions.
