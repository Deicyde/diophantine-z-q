# Implementation note: Lowering to primitive programs

- Lean names: `ZInQ.Compiler.IR.code (s : Stmt) (start : ℕ) (aux : ℕ) : List RM.Instr × ℕ`
  (instructions with absolute targets, and the next free auxiliary register),
  `IR.lower (P : IR.Program) : RM.Program`, `IR.lower_valid`.
- Draft: blocks as functions `clearBlock x start`, `moveBlock`, `copyBlock x y t start`,
  `addBlock`, `monusBlock`, `mulBlock`, `divModBlock`, `ltTestBlock`, each returning its
  instruction list and length; `code` concatenates with computed offsets; `lower` appends
  the cleanup (one clearing loop per register below `r`) and the final halt, and places the
  reject self-loop.
- Mathlib: `List.length_append`, `List.getElem_append`.
- Upstream reuse: none. The upstream interpreter assembler and the S22 lowering are not
  available; the same blocks serve the interpreter (see the universal-interpreter note).
- FINITE COMPUTATION: no. Difficulty: medium (≈200 lines; offsets).

## From the deleted duplicate `compiler/translation/machine/lowering.md`

- Reproduction issue: the witness counts of the syntax chapter (54,051 explicit witnesses,
  15,845 power calls) depend on the exact universal interpreter (1,399 states, 204
  registers), produced by upstream's primitive assembler, which is not in this repository. The
  lowering used for the interpreter must reproduce it (see the universal-interpreter note), or
  the counts must be recomputed within 292,890,231,904 witnesses. The lowering of the
  precision program only affects `c_3`, so any correct lowering is acceptable there, at the
  cost of a literal that differs from the saved one in the external cross-check.
