# Implementation note: Decoding a program code

- Lean names: `ZInQ.Machine.decodedStep_code`, `ZInQ.Machine.decodedHalts_code_iff`,
  `ZInQ.Machine.code_ge_five`.
- Draft:
  ```lean
  theorem decodedStep_code (prog : Prog) (c : Config) : decodedStep (code prog) c = step prog c
  theorem decodedHalts_code_iff (prog : Prog) (n : ℕ) : DecodedHalts (code prog) n ↔ prog.Halts [n]
  theorem code_ge_five (prog : Prog) (h : ∃ i ∈ prog, i ≠ .halt) : 5 ≤ code prog
  ```
- Proof: uniqueness of `2^w * odd` (`Nat.eq_two_pow_mul_odd` style lemmas or
  `Nat.factorization_eq_of_coprime`), digits of `∑ dᵢ Bⁱ` with `dᵢ < B`
  (`Nat.digits_ofDigits` checked; or a direct `Nat.div_mod` computation
  `(∑ dᵢ Bⁱ) / B^k % B = d_k`).
- Mathlib: `Nat.ofDigits`, `Nat.digits_ofDigits`, `Nat.ofDigits_digits`.
- Upstream reuse: `lean/ZInQ/HammingDigits.lean` and `BinomialDigit.lean` contain base-`B`
  digit lemmas; check for reusable `ofDigits` facts before reproving.
- FINITE COMPUTATION: no.
- Difficulty: medium (~150 lines, digit arithmetic).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
