# Implementation note: Scope conditions of the natural precision circuit

- Lean names: `ZInQ.Translation.powerTemplate_wellFormed`,
  `ZInQ.Translation.precisionCircuit_wellFormed`, `ZInQ.Machine.c3_ge_two`.
- FINITE COMPUTATION (except `c_3 ≥ 2`). Decidable forms:
  ```lean
  theorem powerTemplate_wellFormed : NatCircuit.WellFormed powerTemplate powerTemplate 82 ∧
      powerTemplate.explicitVars.map Prod.fst = List.range 82 ∧
      powerTemplate.callCount = 0 ∧ powerTemplate.nontrivialConsts = [4, 2, 3]
  theorem precisionCircuit_wellFormed :
      NatCircuit.WellFormed powerTemplate precisionCircuit 1305811
  theorem c3_ge_two : 2 ≤ c3   -- from c3 = code (wrapper precisionMachine), not by evaluation
  ```
  The power template has 474 nodes; `decide` (kernel) is feasible for item 1 once the template
  is a concrete term. Item 2 has 293,620 nodes, 54,056 explicit variables and 15,845 blocks;
  the head node is `const c3`, so the checker must not force `c3`: state `const_ge_two` for the
  specialized circuit as `c = c3 ∨ c ∈ [2, 4, 1399]` and discharge `c3` by `c3_ge_two`.
- Method, preferred: prove item 2 by construction from the natural chapter's compiler (its
  allocator hands out consecutive explicit indices and blocks, and the specialization shifts
  them by 7), so no 293,620-node check is needed. Fallback: a Boolean checker over the circuit
  (sorted block starts, interval disjointness by a merge pass, var-node membership via a
  `Std.HashSet` in compiled code or a sorted-list search in the kernel), proved sound, run with
  `native_decide` at milestone 1 and replaced by the by-construction proof at milestone 2.
- `c3_ge_two`: from `program-numbering-decode` (`code prog ≥ 5` when `Π` has a non-halt
  instruction; the wrapper's first instruction is not `halt`).
- Mathlib: `List.Nodup`, `List.range`, `decide`.
- Upstream reuse: none.
- Difficulty: low for item 1; medium for item 2 by construction (depends on the natural
  chapter's compiler definitions).

Shared design (translation notes): namespace `ZInQ.Translation`, files under
`ZInQKernel/Compiler/Translation/`. Reuse the syntax chapter's `ZInQ.Syntax.NatCircuit`,
`ZInQ.Syntax.translate`, `ZInQ.Syntax.Rel`, `ZInQ.Syntax.pointRef` and the model chapter's
`ZInQ.iota`. The multiplication statement is taken as a hypothesis
`hM : ZInQ.MultiplicationExact`, where
`def MultiplicationExact : Prop := ∀ p q r : Fin 5 → ℚ, Syntax.Rel multiplyPoly 15 35134 (p ++ q ++ r) ↔ ∃ a b : ℤ, p = iota a ∧ q = iota b ∧ r = iota (a * b)`
(to be shared with the multiplication chapter; if that chapter instead proves the statement
from H, PC, MW, 22P, CAT, the assembly instantiates `hM` with that theorem). `iota` is never
evaluated; constants `c_3`, `A_ht` stay symbolic.
