# Implementation note: The universal interpreter

- Lean name: `ZInQ.Compiler.Universal.interpreter : RM.Program`.
- Two acceptable definitions, the first preferred:
  1. a structured assembly (blocks of the two block articles with an explicit register map)
     whose output is checked equal to the recovered literal by `decide` (equality of two
     1,399-element lists of small instructions; feasible in the kernel), so that the
     compiled counts equal the specification's exactly;
  2. the literal itself (generated from the saved circuit by the recovery described in the
     shared design note), with correctness proved by first proving
     `interpreter = assemble interpreterSpec` by `decide`.
  If neither reproduces the recovered program exactly, the compiled circuit's counts change
  and the syntax chapter's witness accounting must be redone (more instructions or
  registers would exceed the variable budget, which has no slack).
- Register roles in the recovered program: `0 = e`, `1 = n`, `2` = jump register. States
  0-1 clear registers 17 and 19, and states 2-8 copy register 0 into register 17 using
  register 19 as the counter. The cleanup is states 1194-1397, `dec j (self) (next)` with
  `j = state - 1194` for `j = 0..203`; it is entered from states 69, 587 and 593. State 1398
  is the final halt.
- Mathlib: none.
- Upstream reuse: none (the interpreter source is in the research archive, not here).
- FINITE COMPUTATION: the equality check of option 1/2 (1,399 instructions, kernel `decide`).
- Difficulty: hard (reverse-engineering the assembler; ≈400 lines).
