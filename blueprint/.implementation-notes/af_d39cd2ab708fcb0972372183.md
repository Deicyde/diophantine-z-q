# Implementation note: Parameter and witness counts of the templates

- Lean name: `ZInQ.Syntax.library_counts`.
- FINITE COMPUTATION. Decidable form:
  ```lean
  theorem library_counts :
      library.map (fun t => (t.parameterCount, t.variableCount - t.parameterCount)) =
        [(5,7), (15,6), (7,1), (7,0), (4,0), (1,11), (44,162), (22,1298), (36,35106),
         (10,1), (15,1), (15,35134), (5,140604), (10,140654), (2,4), (16,53), (11,35282),
         (6,406), (10,1), (10,1), (10,1), (10,1), (10,1)] := by decide
  ```
  Prove it through `Prog.count` (the allocation counter), which equals `variableCount` by the
  construction theorem, so the kernel evaluates only counters, never nodes or constants.
- Size: 23 small programs (at most a few thousand allocation steps each).
- Method: `decide`/`rfl` in the kernel directly (cheap: no fixed constant is touched, the
  `integerConstant` values only appear as unevaluated `FixedExpr.ref`s). `native_decide` is
  not needed. If `decide` is slow on the larger programs, use `Nat.decEq` via `rfl` on
  `Prog.count` per template.
- Mathlib: none.
- Upstream reuse: none.
- Difficulty: low.
