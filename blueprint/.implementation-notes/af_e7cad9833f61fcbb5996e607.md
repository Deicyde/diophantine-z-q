# Implementation note: The lowered machine halts exactly on acceptance

- Lean names: `ZInQ.Machine.lower_accepts_of_accepts`, `ZInQ.Machine.accepts_of_lower_halts`,
  `ZInQ.Machine.lower_halts_iff`.
- Draft:
  ```lean
  theorem lower_halts_iff (S : Stmt) (x : List ℕ) (hx : x.length ≤ S.regBound) :
      (lower S).Halts x ↔ S.Accepts x
  theorem lower_accepts_iff (S : Stmt) (x : List ℕ) (hx : x.length ≤ S.regBound) :
      (lower S).Accepts x ↔ S.Accepts x
  ```
- Proof: block simulation lemma by induction on `Exec` (forward) and on the number of machine
  steps (backward), with an invariant relating machine registers to structured registers
  (agree below `regBound`, auxiliaries zero). Use `StateTransition.Respects`/`tr_eval` for the
  forward direction and `StateTransition.tr_eval_rev` or a direct step induction backward.
  Macro lemmas (copy restores the source; add with snapshot; subtraction; multiplication by
  repeated addition; guarded divmod maintaining `x = q*y + r`; preserving tests) are separate
  small lemmas.
- Mathlib: `StateTransition.tr_eval`, `StateTransition.tr_eval_rev`,
  `StateTransition.Reaches`, `Relation.ReflTransGen`.
- Upstream reuse: none (the upstream helpers do not cover register machines).
- FINITE COMPUTATION: no.
- Difficulty: high (~600 lines; split into one PR per macro family plus the control-flow PR).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
