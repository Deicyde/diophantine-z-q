# Implementation note: The precision predicate

- Lean names: `ZInQ.Machine.encInt : ℤ → ℕ`, `ZInQ.Machine.decInt : ℕ → ℤ`,
  `ZInQ.Machine.contactSix (u : ℤ) : ℤ`, `ZInQ.Machine.Aht0 : ℕ`, `ZInQ.Machine.zCoord`,
  `ZInQ.Machine.Nondegenerate`, `ZInQ.Machine.acceptsNaturals : (Fin 5 → ℕ) → Prop`.
- Draft:
  ```lean
  def decInt (c : ℕ) : ℤ := if c % 2 = 0 then (c / 2 : ℕ) else -((c + 1) / 2 : ℕ)
  noncomputable def Aht0 : ℕ := 2 * 10 ^ 13 * max 1 (max heightCcmNat (heightDNat ^ (17 * heightDNat * heightE0Nat)))
  def Nondegenerate (Q : genCurve.toAffine.Point) : Prop :=
    ∃ x y h, Q = .some x y h ∧ x ≠ 0 ∧ y ≠ 0
  noncomputable def zCoord : genCurve.toAffine.Point → K0 | .some x y _ => -x / y | _ => 0
  def acceptsNaturals (c : Fin 5 → ℕ) : Prop :=
    let n := decInt (c 0); let κ := decInt (c 1); let a := decInt (c 2); let l := decInt (c 3)
    let j := decInt (c 4)
    n ∉ ({0, -15, -20, -24, -30, -60} : Finset ℤ) ∧ κ ≠ 0 ∧ 1 ≤ a ∧ 1 ≤ l ∧ j = n * a ∧
    Nondegenerate (l • genP0) ∧ Nondegenerate (a • genP0) ∧ Nondegenerate (j • genP0) ∧
    let ε := |(zCoord (l • genP0)).re| + |(zCoord (l • genP0)).im|
    let r := (zCoord (j • genP0) / zCoord (a • genP0)).re   -- = ½ Tr
    |r - n| < ε ∧ 4 * ε < (4 : ℚ) ^ (-(Aht0 * (κ * contactSix n).natAbs ^ 24 : ℤ))
  ```
  `heightDNat` etc. are the natural-number versions of `heightD`, `heightE0`, `heightCcm` in
  `ZInQKernel/Hypotheses/Height.lean`; prove `(Aht0 : ℝ) = heightH6 heightD` once (used by the
  assembly chapter with the six-contact hypothesis at `R = D`). For `x + y s` in `K0 =
  QuadraticAlgebra ℚ 2 0`, `½ Tr = re`.
- The second test is never decided by evaluating `4 ^ B`; proofs use the capped-arithmetic
  lemmas.
- Coordination: the natural chapter's (C.4) must use this predicate.
- Mathlib: `QuadraticAlgebra` (`re`, `im`), `zpow` on `ℚ`, `Int.natAbs`.
- Upstream reuse: `ZInQ.PrecisionArithmetic.four_mul_pow_lt_iff` for the integer form.
- FINITE COMPUTATION: no.
- Difficulty: low (definitions, ~80 lines).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
