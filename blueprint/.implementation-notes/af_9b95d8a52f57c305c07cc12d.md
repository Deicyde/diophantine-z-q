# Implementation note: Template heights

- Lean name: `ZInQ.Size.template_heights`, `ZInQ.Size.template_consts_small`,
  `ZInQ.Size.template_constructor_exprs`.
- FINITE COMPUTATION. Decidable form:
  ```lean
  def heightTable : List ℕ := [18, 21, 12, 12, 25, 24, 79, 169, 207, 17, 4, 214, 223, 230, 9, 34,
    249, 43, 17, 17, 17, 17, 17]
  theorem template_heights :
      List.Forall₂ (· ≤ ·) (libraryHeights Syntax.library) heightTable := by decide
  theorem template_consts_small :
      (Syntax.library.flatMap (·.nodes)).countP Syntax.Node.isConst = 173 ∧
      ∀ τ ∈ Syntax.library, ∀ c, Syntax.Node.const c ∈ τ.nodes → c.natAbs < 2 ^ 69 := by decide
  theorem template_constructor_exprs :
      ∀ τ ∈ Syntax.library, ∀ n ∈ τ.nodes, Syntax.Node.fixedExprOK n = true := by decide
  -- fixedExprOK: fixed e → e = .ref .ell; guard e _ → e = .ref .T;
  --   psi e _ _ → e ∈ indexExprs (ε, add ε (lit 1), add ε (lit (-1)), mul (lit 2) ε for
  --   ε ∈ [.ref .cstar, .ref (.integerConstant 0), …, .ref (.integerConstant 4)])
  ```
  plus the count of constructor nodes (48 psi, 1 guard, 1 fixed).
- Size: 23 node lists, about 7100 nodes; `decide` needs `DecidableEq FixedExpr` (derive it) and a
  computable `Syntax.library` (the `Prog.dag` interpreter, which hash-conses: make sure it uses a
  list-based lookup that the kernel can reduce, or provide the node lists also as literals with
  an `rfl` proof that `Prog.dag` produces them).
- Method: kernel `decide` (or `decide +kernel`) on these closed statements. Risk: reducing
  `Prog.dag` in the kernel may be slow; fallback for milestone 1 is `native_decide` in the separate
  non-audited library, and for milestone 2 a CFSG-style certificate: pin each template's node
  list as a literal `List Node`, prove `Prog.dag prog = literal` by `rfl` per template (23 small
  proofs), and run the height and expression checker on the literals by `Eq.refl true`. The
  literals contain `FixedExpr` trees and small integer constants only: the program literal `c_3`
  is referenced by name (`integerConstant 3`) and never appears as a number in a node.
- Mathlib: none.
- Upstream reuse: none; the numbers are those of construction/ordinary-integer-polynomial-size-bounds.json.
- Difficulty: low with `native_decide`; medium for the kernel route.

Shared design (majorant notes): `Maj B h P : Prop := if h = 0 then P.totalDegree ≤ 1 ∧ l1 P ≤ 1
else P.totalDegree ≤ B ^ (8 * h) ∧ l1 P ≤ 2 ^ B ^ (8 * h)` (helper def in `ZInQKernel/Size/Majorant.lean`).
Heights are computed on the syntax chapter's node lists (`ZInQ.Syntax.Template.nodes`, produced by
`Prog.dag`), so they depend only on syntax, never on the values of fixed expressions.
