# Implementation note: Node statistics of the halting circuit and the power template

- Item 2 is proved in the kernel: `ZInQ.Compiler.Universal.powerTemplate_nodeStats` and
  `powerTemplate_nodes_length` (`decide +kernel` on the 474 nodes, about 35 s).
- Item 1 is the named finite check `ZInQ.Compiler.Universal.HaltingNodeCheck`, a closed
  decidable proposition: the counts of variable, constant, addition and multiplication nodes of
  `haltingCircuit.nodes` and its constant list `[0, 1, 2, 4, 1399, -1]`.
  `haltingCircuit_nodeStats` derives item 1 from it; the call count, the first two nodes, the
  distinctness of the non-call nodes and the membership of every constant in
  `{0, 1, 2, 4, -1, 1399}` (`haltingCircuit_consts`) are proved outright.
- Reduced to a Boolean computation: `ZInQ.Compiler.NodeCheck.haltingNodeCheck_of_checkB :
  haltingNodeCheckB = true → HaltingNodeCheck` (`ZInQKernel/Compiler/NodeCheck/`, axioms
  `propext`, `Classical.choice`, `Quot.sound`), through a fast builder that keeps only node
  indices in a binary trie and is proved equal to the list-based builder.
- Milestone 1 (done): `ZInQ.Compiler.Universal.haltingNodeCheck_native` in the separate library
  `ZInQFinite` closes `haltingNodeCheckB = true` by `native_decide` (the whole library builds in
  about 30 s). Open: the same Boolean by kernel evaluation.
- Kernel routes (milestone 2). Running the builder as it is takes far too long in the kernel
  (the 474-node power template alone takes about 30 s).
  - A verified fast builder: parametrize the builder over its node-insertion primitive and run
    it with an indexed map such as a `Nat`-keyed trie, with a Boolean checker proved by
    `Eq.refl true`.
  - An exact symbolic count of the hash-consing events. The constructor emits 129,408
    additions and 98,727 multiplications; hash-consing removes 4,101 additions (2,452 re-sums
    `z + a` in bitAnd, 1,601 re-sums `N + 1` in the mask binomials, 48 in items 6–7) and 366
    multiplications (204 `K·F` in the register masks, 151 in items 6–7, 11 in the formula
    encoding). Only the 199 events in items 6–7 depend on the program.
  - The variable-node count (54,049) and the presence of the six constants can come from
    extending the `Grows` judgement; the check then needs only the addition and multiplication
    counts and the constant order.
- Upper bounds from counting constructor calls are not enough: the witness accounting has no
  slack, and they overshoot by about 12.9 million witnesses (each addition node costs 6
  witnesses, each multiplication node 35,134). Downstream needs only the two upper bounds
  `countKind .add ≤ 125307` and `countKind .mul ≤ 98361`, which are tight.
