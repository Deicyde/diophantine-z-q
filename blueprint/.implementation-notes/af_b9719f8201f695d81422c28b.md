# Implementation note: Fixed integer expressions

- Lean names: `ZInQ.Syntax.FixedExpr`, `ZInQ.Syntax.FixedExpr.val`.
- Draft:
  ```lean
  inductive FixedExpr
    | literal (z : ℤ) | ref (c : FixedConst)
    | add (a b : FixedExpr) | mul (a b : FixedExpr) | pow (a b : FixedExpr)
    | max (a : FixedExpr) (as : List FixedExpr) | factorial (a : FixedExpr)
    | catalogueProduct (W k B : FixedExpr) | catalogueMax (W k B : FixedExpr)
    | leastFormalMultiple (N : FixedExpr)
  noncomputable def FixedExpr.val : FixedExpr → ℤ
  ```
  `FixedConst` is an enumeration of the named constants in specification order with
  `FixedConst.expr : FixedConst → FixedExpr` referring only to earlier constants;
  `val (.ref c)` recurses on the constant's position (well-founded on the order).
  `pow a b = val a ^ (val b).toNat`, `factorial a = (val a).toNat !`.
- Mathlib: `Nat.factorial`, `Int.toNat`, `List.maximum?`/`List.foldl max`.
- Upstream reuse: none for the syntax; the evaluator mirrors `evaluateFixed` in
  construction/finite-polynomial-expressions.js (which refuses to evaluate the catalogue and
  formal-multiple operators).
- Finite computation: no. `val` is noncomputable and never evaluated on astronomical
  constants; proofs use `simp [FixedExpr.val]` to reach the defining formulas.
- Difficulty: low (~80 lines).

Shared design (all syntax notes): namespace `ZInQ.Syntax`, files under
`ZInQKernel/Syntax/`. Polynomials are `MvPolynomial ℕ ℤ`; evaluation over `ℚ` is
`MvPolynomial.eval₂ (Int.castRingHom ℚ) x`. Templates are written once as programs of a
small deep-embedded construction language `Prog` (free monad over: fresh variable, fresh
block call, rational constant, node operations, formula connectives) with three
interpreters: `Prog.dag` (hash-consed node list, mirrors the JS builder byte for byte, used
for heights and the cross-check), `Prog.formula` (readable `Formula` term, used for
semantics) and `Prog.count` (allocation counter only, cheap to evaluate in the kernel).
Fixed integer expressions stay symbolic (`FixedExpr` syntax, noncomputable `val`); no proof
ever evaluates `c_*`, `ell`, `T`, `D`, `Q` or the program literal `c_3`.
