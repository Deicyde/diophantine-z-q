# Implementation note: The cutoff is below a triple tower

- Lean name: `ZInQ.Size.closedT_lt` (and in the cutoff note `T_lt`).
- Draft:
  ```lean
  theorem closedT_lt :
      (96 * 10 ^ 13) ^ 13 * Syntax.D ^ (2210 * Syntax.G0 ^ 2 * Syntax.D ^ 3) <
        NumericalTowerBounds.triplePower 9013
  ```
  (`triplePower a = 2 ^ 2 ^ 2 ^ a`.)
- Upstream reuse: this is exactly `ZInQ.ExplicitCutoffBounds.t_lt_triplePower`
  (lean/ZInQ/ExplicitCutoffBounds.lean), which is public and sorry-free; rewrite with
  `Syntax.D = ExplicitCutoffBounds.d`, `Syntax.G0 = ExplicitCutoffBounds.g0` and apply it. The
  intermediate `2 ^ (D ^ 8)` bound is inside the private `arithmetic_bound`; expose it only if
  needed.
- Mathlib: none beyond upstream.
- Finite computation: no (upstream's proof uses `decide` only on closed small literals and on
  `324!`).
- Difficulty: low (a few lines given upstream).

Shared design (size notes): namespace `ZInQ.Size`, files under `ZInQKernel/Size/`. Constants are
the syntax chapter's abbreviations `ZInQ.Syntax.Ps`, `W`, `Hcat`, `Hmax`, `Ns`, `M0`, `cstar`,
`ell`, `F`, `D`, `G0`, `E0`, `R`, `Q`, `Bcm`, `Ccm`, `Aht`, `T` (natural numbers or `toNat` of
`FixedExpr.val`; prove unfolding lemmas `T_def : T = (48 * Aht)^13` etc. by `rfl`/`simp
[FixedExpr.val]`). None of them is ever evaluated: never `decide`, `norm_num` or `rfl`-reduce a
goal containing `D`, `T`, `Hcat`, `M0`, `cstar`, `ell` or `c_3`; mark them `@[irreducible]`
after the unfolding lemmas, and work with `Nat.pow_lt_pow_left/right`, `Nat.pow_le_pow_left/right`,
`Nat.lt_two_pow_self`, `Nat.mul_lt_mul_of_lt_of_lt` as in upstream
`ZInQ.ExplicitCutoffBounds` (lean/ZInQ/ExplicitCutoffBounds.lean).
