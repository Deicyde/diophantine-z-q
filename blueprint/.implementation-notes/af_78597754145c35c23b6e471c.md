# Implementation note: The universal program numbering

- Lean names: `ZInQ.Machine.decodeParams (e : ℕ) : ℕ × ℕ` (returns `(w, D)`),
  `ZInQ.Machine.digit (B D i : ℕ) : ℕ := D / B ^ i % B`, `ZInQ.Machine.decodedStep (e : ℕ) :
  Config → Option Config`, `ZInQ.Machine.DecodedHalts (e n : ℕ) : Prop`,
  `ZInQ.Machine.code : Prog → ℕ`.
- Draft:
  ```lean
  def decodeParams (e : ℕ) : ℕ × ℕ := ((e + 1).factorization 2, ((e + 1) / 2 ^ (e + 1).factorization 2 - 1) / 2)
  def code (prog : Prog) : ℕ := let w := codeWidth prog; 2 ^ w * (2 * codeDigits prog w + 1) - 1
  ```
  Use `Nat.maxPowDvdDiv 2` (Mathlib/Data/Nat/MaxPowDiv.lean) or `padicValNat 2` for `w`; the
  computable form matters only for small tests, never for `c_3`.
- Mathlib: `Nat.exists_eq_two_pow_mul_odd` (checked), `padicValNat`, `Nat.ofDigits`,
  `Nat.digits`.
- Upstream reuse: none.
- FINITE COMPUTATION: no.
- Difficulty: low (~60 lines).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
