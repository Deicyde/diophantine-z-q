# The 2-adic valuations of the coordinates of P0 (generator-dyadic-numerals)

- Lean name: `ZInQ.Mult.genP0_dyadic_numerals`.
- Decidable statement:
  ```lean
  theorem genP0_dyadic_numerals :
      padicValNat 2 1641 = 0 ∧ padicValNat 2 1160 = 3 ∧ padicValNat 2 123720 = 3 ∧
      padicValNat 2 87483 = 0 ∧ padicValNat 2 8 = 3 ∧ padicValNat 2 32 = 5
  ```
  If `decide` does not reduce `padicValNat` (it is defined through `Nat.find`/`multiplicity`),
  prove the equivalent closed form
  `1641 % 2 = 1 ∧ 87483 % 2 = 1 ∧ 1160 = 2^3 * 145 ∧ 145 % 2 = 1 ∧ 123720 = 2^3 * 15465 ∧ 15465 % 2 = 1`
  by `decide` and convert with `padicValNat.mul`, `padicValNat.prime_pow` and
  `padicValNat.eq_zero_of_not_dvd` (verified in Mathlib/NumberTheory/Padics/PadicVal/Basic.lean).
  Mathlib v4.35.0 has no `norm_num` extension for `padicValNat` (checked: none under
  Mathlib/Tactic/NormNum).
- FINITE COMPUTATION: yes. Size: numbers below 2·10^5. Method: kernel `decide` on the closed form.
- Difficulty: trivial.

Shared design (multiplication chapter): namespace `ZInQ.Mult`, files under
`ZInQKernel/Multiplication/`. Points are `genCurve.toAffine.Point` over `K0 = QuadraticAlgebra ℚ 2 0`;
codes are `ZInQ.iota`; template relations are `ZInQ.Syntax.Rel`. Valuations on `K0` at a prime
`𝔭 : IsDedekindDomain.HeightOneSpectrum Zs` (with `Zs` the model chapter's `ℤ[√2]`) are taken as
`ℤ∪{∞}`-valued via `IsDedekindDomain.HeightOneSpectrum.valuation K0 𝔭` (multiplicative, `ℤᵐ⁰`);
a thin wrapper `ZInQ.Mult.vP 𝔭 : K0 → WithTop ℤ` is recommended. The completion is
`𝔭.adicCompletion K0`. The constants `c_*`, `ℓ_0`, `A_ht`, `T` are the syntax chapter's symbolic
`FixedExpr` values and are never evaluated (no `decide`/`norm_num` on them).
