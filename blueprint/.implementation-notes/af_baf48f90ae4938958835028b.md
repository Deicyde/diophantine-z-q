# Implementation note: Structured register programs

- Lean names: `ZInQ.Machine.Stmt`, `ZInQ.Machine.Outcome`, `ZInQ.Machine.Exec`,
  `ZInQ.Machine.Stmt.Accepts`, `ZInQ.Machine.Stmt.Total`, `ZInQ.Machine.Stmt.regBound`.
- Draft:
  ```lean
  inductive Stmt
    | zero (r) | inc (r) | dec (r) | copy (r r') | add (r r' r'') | sub (r r' r'')
    | mul (r r' r'') | divmod (q m r' r'') | seq (s t : Stmt) | ifz (r) (s t : Stmt)
    | iflt (r r') (s t : Stmt) | while (r) (s : Stmt) | accept | reject
  inductive Outcome | cont (R : ℕ → ℕ) | acc (R : ℕ → ℕ) | rej (R : ℕ → ℕ)
  inductive Exec : Stmt → (ℕ → ℕ) → Outcome → Prop   -- big-step rules
  def Stmt.Accepts (S : Stmt) (x : List ℕ) : Prop := ∃ R, Exec S (init x).reg (.acc R)
  ```
  For the precision program and the interpreter, also give a fuel-based evaluator
  `Stmt.run (fuel : ℕ) : (ℕ → ℕ) → Option Outcome` with `run_sound`/`run_complete`, so that small
  instances can be tested by `#eval` (never for proofs about `c_3`).
- Mathlib: none special.
- Upstream reuse: none.
- FINITE COMPUTATION: no.
- Difficulty: low (~120 lines).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
