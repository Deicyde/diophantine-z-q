# Implementation note: Template construction from formulas

- Lean name: `ZInQ.Syntax.Prog.denote_dag`.
- Draft:
  ```lean
  theorem Prog.denote_dag (c : Prog Formula) (p : ℕ) (lib : Library) (hlib : lib.WellFormed) :
      (c.toTemplate name p).denote lib.polys = (c.formulaAt p).compileWithGlobals ∧
      (c.toTemplate name p).variableCount = c.count p
  ```
- Proof: induction on `c` with invariant `∀ i < st.nodes.length, nodeDenote st i = shadow i`;
  the hash-consing cache maps a key to an index whose stored node is equal to the key.
  Use an association list (`List (Node × ℕ)`) for the cache inside proofs; if the DAG
  interpreter uses `Std.HashMap` for speed, prove `find?` agrees with the list lookup or keep
  the hash map only in the cross-check executable.
- Mathlib: `MvPolynomial` ring lemmas; `List.getElem_append_left`.
- Upstream reuse: none.
- Finite computation: no.
- Difficulty: medium-high (~300 lines; the hash-consing invariant is the delicate part).
  Fallback if this proves costly: drop hash-consing from the Lean DAG interpreter (the node
  list is then longer than the saved one but denotes the same polynomial, and heights are
  unchanged because sharing does not affect the height recursion); the cross-check then
  compares polynomials by randomized evaluation rather than node lists.

Shared design (all syntax notes): namespace `ZInQ.Syntax`, files under
`ZInQKernel/Syntax/`. Polynomials are `MvPolynomial ℕ ℤ`; evaluation over `ℚ` is
`MvPolynomial.eval₂ (Int.castRingHom ℚ) x`. Templates are written once as programs of a
small deep-embedded construction language `Prog` (free monad over: fresh variable, fresh
block call, rational constant, node operations, formula connectives) with three
interpreters: `Prog.dag` (hash-consed node list, mirrors the JS builder byte for byte, used
for heights and the cross-check), `Prog.formula` (readable `Formula` term, used for
semantics) and `Prog.count` (allocation counter only, cheap to evaluate in the kernel).
Fixed integer expressions stay symbolic (`FixedExpr` syntax, noncomputable `val`); no proof
ever evaluates `c_*`, `ell`, `T`, `D`, `Q` or the program literal `c_3`.
