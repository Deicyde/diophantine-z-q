# The formal neighbourhood of y^2=x^3+Ax and its filtration (formal-group)

- Lean names: `ZInQ.Mult.formalNbhd` (the subgroup `W₁(K)`), `ZInQ.Mult.formal_val_x_y`,
  `ZInQ.Mult.formalFilt` (the subgroups `W_k`), `ZInQ.Mult.z_injective_formal`,
  `ZInQ.Mult.val_z_zsmul_ge`.
- Draft (any field with a discrete valuation; no completeness needed):
  ```lean
  variable {K : Type*} [Field K] [CharZero K] (v : Valuation K (WithZero (Multiplicative ℤ)))
  def W (A : K) : WeierstrassCurve K := ⟨0, 0, 0, A, 0⟩
  def formalFilt (A : K) (hA : v A ≤ 1) (k : ℕ) (hk : 1 ≤ k) : AddSubgroup (W A).toAffine.Point
  theorem z_injective_formal ... : Set.InjOn zCoord (formalFilt A hA 1 le_rfl)
  theorem val_z_zsmul_ge (P ∈ formalFilt A hA 1 _) (n : ℤ) : vz P ≤ vz (n • P)   -- additive valuation
  ```
  Instantiate with `K = K0` and `v = 𝔭.valuation K0` (so no completion is needed for the
  integrality and dyadic arguments), and with `K = 𝔭.adicCompletion K0` where the logarithm is
  used.
- Proof route: the article's chord computation in the coordinates `(z, ω) = (-x/y, -1/y)`. In Lean,
  avoid projective geometry: for affine `P₁ + P₂` with `P₁ ≠ -P₂`, Mathlib's addition gives
  `x₃ = ℓ² - x₁ - x₂`, `y₃ = -(ℓ(x₃ - x₁) + y₁)` (`WeierstrassCurve.Affine.addX`, `addY`,
  `slope`); verify `z(P₁ + P₂) = -z₃` with `z₃ = -z₁ - z₂ - 2Aλν/(1 + Aλ²)` by `field_simp; ring`
  after substituting `λ = -ℓ/m`, `ν = -1/m`, `m = y₁ - ℓx₁`. The case `m = 0` does not occur
  for `P₁, P₂ ∈ W₁`: the `(x,y)`-line `y = ℓx` is the vertical line `z = -1/ℓ` of the
  `(z,ω)`-plane, whereas the chord or tangent through `P₁, P₂` there has the finite slope `λ`
  (and `z₁ ≠ z₂` unless `P₁ = P₂`). The case `x₁ = x₂, y₁ = -y₂` is `P₁ + P₂ = 0`. The valuation
  bookkeeping uses `Valuation.map_add`, `Valuation.map_mul`, `Valuation.map_add_eq_of_lt_left` (verified).
- Mathlib: `WeierstrassCurve.Affine.Point` (group law), `Valuation`, `AddSubgroup`. Mathlib has
  `FormalGroup` (Mathlib/RingTheory/FormalGroup/Basic.lean) but nothing about the formal group
  of an elliptic curve; this article does not need it.
- FINITE COMPUTATION: no. Difficulty: medium (~300-500 lines; the case analysis of the addition
  formulas is the bulk).

Shared design (multiplication chapter): namespace `ZInQ.Mult`, files under
`ZInQKernel/Multiplication/`. Points are `genCurve.toAffine.Point` over `K0 = QuadraticAlgebra ℚ 2 0`;
codes are `ZInQ.iota`; template relations are `ZInQ.Syntax.Rel`. Valuations on `K0` at a prime
`𝔭 : IsDedekindDomain.HeightOneSpectrum Zs` (with `Zs` the model chapter's `ℤ[√2]`) are taken as
`ℤ∪{∞}`-valued via `IsDedekindDomain.HeightOneSpectrum.valuation K0 𝔭` (multiplicative, `ℤᵐ⁰`);
a thin wrapper `ZInQ.Mult.vP 𝔭 : K0 → WithTop ℤ` is recommended. The completion is
`𝔭.adicCompletion K0`. The constants `c_*`, `ℓ_0`, `A_ht`, `T` are the syntax chapter's symbolic
`FixedExpr` values and are never evaluated (no `decide`/`norm_num` on them).
