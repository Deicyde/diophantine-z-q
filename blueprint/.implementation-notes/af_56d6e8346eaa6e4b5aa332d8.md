# Implementation note: Recipes satisfy the height majorant

- Lean names: `ZInQ.Size.model_recipe_maj`, `ZInQ.Size.comp_recipe_maj`.
- Draft:
  ```lean
  theorem model_recipe_maj {B : ℕ} (hB : 2 ^ 20 ≤ B) (r : Syntax.ModelRecord)
      (hcount : (Syntax.ModelRecord.constraints r).length ≤ B) (h : ℕ)
      (hcallees : ∀ κ ∈ Syntax.ModelRecord.callees r, Maj B h κ.poly) :
      Maj B (max 4 (h + 3) + 2) (Syntax.Recipe.denote (.model r))
  theorem comp_recipe_maj {B : ℕ} (hB : 2 ^ 20 ≤ B) (ρ : Syntax.Recipe) (h : ℕ) ... :
      Maj B (h + 2) (denote ρ)   -- sum of squares; `h + 1` for products
  ```
  Stating with a single bound `h` for all callees (rather than `max_κ h_κ`) is simpler and
  equivalent after `Maj.mono`.
- Proof: the constraint list of a model record (syntax chapter, recipe semantics): generator
  constraints and root differences by direct `l1`/degree computation (`l1 (C 8 * X g - C 1641) ≤
  1649`), calls by `Maj.bind₁` with arguments from `Syntax.pointRef` (`Maj B 2`), then
  `Maj.sum_sq`. Composition calls: `callPoly` with variable arguments is a `rename`, so
  `Maj.rename`; then `Maj.sum_sq` or `Maj.prod`.
- Mathlib: `MvPolynomial.bind₁_X_right`, `MvPolynomial.rename_X`, `MvPolynomial.algHom_ext`
  (to prove the small missing identity `bind₁ (X ∘ f) = rename f` on generators), and
  `MvPolynomial.bind₁_comp_rename` (Mathlib/Algebra/MvPolynomial/Monad.lean:218).
- Finite computation: no. The precision record is never traversed; only its length (from the
  closed-form count lemma of the translation) and the set of callees (structural) are used.
- Upstream reuse: none.
- Difficulty: medium (~150 lines).

Shared design (majorant notes): `Maj B h P : Prop := if h = 0 then P.totalDegree ≤ 1 ∧ l1 P ≤ 1
else P.totalDegree ≤ B ^ (8 * h) ∧ l1 P ≤ 2 ^ B ^ (8 * h)` (helper def in `ZInQKernel/Size/Majorant.lean`).
Heights are computed on the syntax chapter's node lists (`ZInQ.Syntax.Template.nodes`, produced by
`Prog.dag`), so they depend only on syntax, never on the values of fixed expressions.
