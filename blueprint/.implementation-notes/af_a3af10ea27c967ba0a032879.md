# Correctness of the multiplication template (multiplication-template)

- Lean name: `ZInQ.Mult.multiply_rel_iff` (input M).
- Draft:
  ```lean
  theorem multiply_rel_iff (hH : SixContactEstimate) (hPC : PoleCompleteness) (hMW : MordellWeilE)
      (h22 : FixedPrimePattern) (Y : Fin 15 → ℚ) :
      Syntax.Rel Syntax.multiplyTemplate.denote 15 35134 Y ↔
        ∃ a b : ℤ, Y = tripleCode (iota a) (iota b) (iota (a * b))
  ```
  (`tripleCode` = point-major concatenation, as in the guard note). Use the exact `Rel` and
  template names of the syntax chapter once they exist.
- Proof: `⟨soundness hH hMW Y, fun ⟨a, b, h⟩ => h ▸ completeness hPC h22 hMW a b⟩`.
- Hypotheses: soundness uses `hH`, `hMW`; completeness uses `hPC`, `h22`, `hMW`. `CatalogueBound` unused.
- FINITE COMPUTATION: no. Difficulty: trivial (assembly).

Shared design (multiplication chapter): namespace `ZInQ.Mult`, files under
`ZInQKernel/Multiplication/`. Points are `genCurve.toAffine.Point` over `K0 = QuadraticAlgebra ℚ 2 0`;
codes are `ZInQ.iota`; template relations are `ZInQ.Syntax.Rel`. Valuations on `K0` at a prime
`𝔭 : IsDedekindDomain.HeightOneSpectrum Zs` (with `Zs` the model chapter's `ℤ[√2]`) are taken as
`ℤ∪{∞}`-valued via `IsDedekindDomain.HeightOneSpectrum.valuation K0 𝔭` (multiplicative, `ℤᵐ⁰`);
a thin wrapper `ZInQ.Mult.vP 𝔭 : K0 → WithTop ℤ` is recommended. The completion is
`𝔭.adicCompletion K0`. The constants `c_*`, `ℓ_0`, `A_ht`, `T` are the syntax chapter's symbolic
`FixedExpr` values and are never evaluated (no `decide`/`norm_num` on them).
