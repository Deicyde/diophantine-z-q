# Implementation note: Jacobian formulas for the group law

- Lean names: `ZInQ.Machine.jacDouble`, `ZInQ.Machine.jacAdd`, `ZInQ.Machine.jacDouble_spec`,
  `ZInQ.Machine.jacAdd_spec`, `ZInQ.Machine.jacP0_spec`.
- Two routes. (a) Use Mathlib's Jacobian coordinates: `WeierstrassCurve.Jacobian.dblXYZ`,
  `addXYZ`, `WeierstrassCurve.Jacobian.Point.toAffine_add` (checked; it needs `Nonsingular`
  hypotheses and `DecidableEq F`) and `toAffine_smul`; the explicit formulas of the article are
  Mathlib's specialized to `a₁ = a₂ = a₃ = a₆ = 0` up to the scaling equivalence. (b) Prove the
  article's formulas directly from the affine group law (`WeierstrassCurve.Affine.Point.add`,
  `addX`, `addY`, `slope`) by `field_simp; ring` / `linear_combination` with the two curve
  equations. Route (b) matches the register program literally and is preferred for the IR.
- Draft:
  ```lean
  theorem jacDouble_spec {X Y Z : K0} (hZ : Z ≠ 0) (hY : Y ≠ 0) (h : Y ^ 2 = X ^ 3 + A * X * Z ^ 4) :
      let T := jacDouble X Y Z; T.2.2 ≠ 0 ∧ T.2.1 ^ 2 = T.1 ^ 3 + A * T.1 * T.2.2 ^ 4 ∧
      toPoint T = 2 • toPoint (X, Y, Z)
  ```
- Mathlib: `WeierstrassCurve.Affine.Point` group law, `WeierstrassCurve.Jacobian` (checked).
- Upstream reuse: `lean/ZInQ/ModelCoordinateIdentities.lean` may contain related identities for
  the model; check before reproving.
- FINITE COMPUTATION: no (polynomial identities; `ring`).
- Difficulty: medium (~200 lines; the case splits are routine but numerous).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
