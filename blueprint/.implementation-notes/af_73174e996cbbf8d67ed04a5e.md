# Implementation note: Values and polynomial of a natural circuit

- Lean names: `ZInQ.Translation.NatCircuit.val`, `NatCircuit.value`, `NatCircuit.poly`,
  `NatCircuit.Admissible`, `NatCircuit.value_eq_eval_poly`.
- Draft:
  ```lean
  def NatCircuit.nodeVals (P : NatCircuit) (N : NatCircuit) (θ : ℕ → ℤ) : List ℤ  -- one pass
  def NatCircuit.value (P N : NatCircuit) (θ : ℕ → ℤ) : ℤ := (N.nodeVals P θ).getD N.root 0
  noncomputable def NatCircuit.poly (P N : NatCircuit) : MvPolynomial ℕ ℤ
  def NatCircuit.Admissible (P N : NatCircuit) (θ : ℕ → ℤ) : Prop :=
    (∀ v ∈ N.explicitVars, v.2 = false → 0 ≤ θ v.1) ∧
    (∀ w ∈ N.callStarts, ∀ i < P.variableCount - 3, 0 ≤ θ (w + i))
  theorem value_eq_eval_poly : N.value P θ = MvPolynomial.eval θ (N.poly P)
  ```
  Use `ℕ → ℤ` assignments with nonnegativity side conditions (simplest for the translation),
  or `ℕ → ℕ` plus casts; pick one and keep it in (C.4) too.
- Mathlib: `MvPolynomial.bind₁`, `MvPolynomial.eval₂Hom_bind₁` (checked), `MvPolynomial.eval`.
- Upstream reuse: `ZInQ.CircuitEncoding.Circuit.eval` is the same recursion over a typed
  `Fin`-indexed circuit; not reused directly (different node format), its proof pattern is.
- Coordination: the natural chapter must define the natural precision polynomial `C` as
  `NatCircuit.poly powerTemplate precisionCircuit` (or prove equality) so that (C.4) and the
  rational translation talk about the same object.
- FINITE COMPUTATION: no.
- Difficulty: low (~80 lines).

Shared design (translation notes): namespace `ZInQ.Translation`, files under
`ZInQKernel/Compiler/Translation/`. Reuse the syntax chapter's `ZInQ.Syntax.NatCircuit`,
`ZInQ.Syntax.translate`, `ZInQ.Syntax.Rel`, `ZInQ.Syntax.pointRef` and the model chapter's
`ZInQ.iota`. The multiplication statement is taken as a hypothesis
`hM : ZInQ.MultiplicationExact`, where
`def MultiplicationExact : Prop := ∀ p q r : Fin 5 → ℚ, Syntax.Rel multiplyPoly 15 35134 (p ++ q ++ r) ↔ ∃ a b : ℤ, p = iota a ∧ q = iota b ∧ r = iota (a * b)`
(to be shared with the multiplication chapter; if that chapter instead proves the statement
from H, PC, MW, 22P, CAT, the assembly instantiates `hM` with that theorem). `iota` is never
evaluated; constants `c_3`, `A_ht` stay symbolic.
