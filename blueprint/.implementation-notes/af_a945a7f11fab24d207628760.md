# Implementation note: Shape of the universal interpreter

- Lean name: `ZInQ.Compiler.Universal.interpreter_shape`.
- FINITE COMPUTATION. Decidable form:
  ```lean
  theorem interpreter_shape :
      interpreter.Valid 204 ∧ interpreter.length = 1399 ∧
      interpreter.subCount = 1022 ∧ interpreter.addCount = 376 ∧
      (∀ j : Fin 204, interpreter[1194 + j]? = some (.dec j (1194 + j) (1195 + j))) ∧
      interpreter[1398]? = some .halt ∧
      ((List.range 1194).filter (fun i => (interpreter[i]?.map RM.Instr.targets).getD [] |>.any (1194 ≤ ·)))
        = [69, 587, 593] ∧
      (∀ i ∈ [69, 587, 593], interpreter[i]? = some (.dec 2 1194 1194)) := by decide
  ```
  The counting consequences (54,049 explicit variables, 15,845 calls, 1,305,804 variables)
  are the separate article "Counts of the universal halting circuit".
- Size: a list of 1,399 instructions with numbers below 1,399. Items 3-4 were checked
  against the saved circuit while reviewing: recovering the state equations
  `S_d = [d=0] + B*(incoming)` from `construction/precision-natural-polynomial.json` gives
  1,022 sub instructions, cleanup `dec j (1194+j) (1195+j)`, and the only states below 1194
  with a target in `[1194,1398]` are 69, 587, 593, each jumping to 1194 on both branches.
- Method: kernel `decide` (`Nat.decEq` on small literals). If `decide` is slow on 1,399
  constructors, write a Boolean checker `shapeB : RM.Program → Bool`, prove
  `shapeB p = true → <statement>`, and close `shapeB interpreter = true` by `rfl`/
  `Nat.decEq`-based `decide` (CFSG style).
- Mathlib: `List.all`, `List.countP`, `List.filter`.
- Upstream reuse: none.
- Difficulty: easy.
