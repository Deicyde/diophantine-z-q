# Implementation note: Recipe heights

- Lean name: `ZInQ.Size.recipe_heights`.
- Draft:
  ```lean
  theorem recipe_heights {B : ℕ} (hB : Admissible B Syntax.library) :
      Maj B 228 (denote powerValueRecipe) ∧ Maj B 233 (denote precisionRecipe) ∧
      Maj B 235 (denote closeRecipe) ∧ Maj B 251 (denote mainRecipe) ∧
      Maj B 252 (denote valueUnionRecipe) ∧ Maj B 254 (denote valueRecipe) ∧
      Maj B 256 (denote integersRecipe)
  ```
- Proof: `template_maj` + `template_heights` + `Maj.mono` give the per-template bounds; the
  constraint counts of the two model records come from the translation's closed-form count
  (`(translate …).constraints.length = 8 + rows + consts + ops`) and
  `ZInQ.Syntax.precisionCircuit_shape`/`powerTemplate_shape` (natural-circuit statistics note):
  `476` and `293622`, each `≤ 2^20` by `decide`; the callee sets are read off the translation
  definition (natural, raw_add, multiply, the scalar templates, the power recipe). Composition
  recipes by `comp_recipe_maj` with `rfl` on their call lists. Final arithmetic by `norm_num`.
- Mathlib: none.
- Finite computation: no (consumes the template-height check and the circuit-shape check).
- Upstream reuse: none.
- Difficulty: low-medium (~100 lines).

Shared design (majorant notes): `Maj B h P : Prop := if h = 0 then P.totalDegree ≤ 1 ∧ l1 P ≤ 1
else P.totalDegree ≤ B ^ (8 * h) ∧ l1 P ≤ 2 ^ B ^ (8 * h)` (helper def in `ZInQKernel/Size/Majorant.lean`).
Heights are computed on the syntax chapter's node lists (`ZInQ.Syntax.Template.nodes`, produced by
`Prog.dag`), so they depend only on syntax, never on the values of fixed expressions.
