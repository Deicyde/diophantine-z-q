# The one-sided pole obstruction (pole-obstruction)

- Lean name: `ZInQ.Mult.pole_obstruction`.
- Draft:
  ```lean
  theorem pole_obstruction (B : ℚ) (hB : B ≠ 0) (hΦ : PoleSoluble B) (p : ℕ) (hp : p.Prime)
      (hpS0 : p ∉ poleS0) : ¬ (padicValRat p B < 0 ∧ Odd (padicValRat p B))
  ```
  with `PoleSoluble`, `poleS0`, `polePoly` from ZInQKernel/Hypotheses/Pole.lean.
- Upstream reuse: `ZInQ.ValuationObstruction.poleSystem_no_negative_odd_valuation`
  (lean/ZInQ/PoleValuation.lean, sorry-free) proves the statement for `poleSystem B v` and
  `¬ p ∣ 2730`. Remaining work: (1) `p ∉ poleS0 ∧ p.Prime → ¬ p ∣ 2730` (`2730 = 2·3·5·7·13`,
  `Nat.Prime.dvd_mul`, decide on the five primes); (2) `polePoly B b e z r₁ r₂ w = 0 → B ≠ 0 →
  poleSystem B ⟨b, e, z, r₁, r₂, w⟩`: `mul_eq_zero`, then a sum of nine squares is zero
  (`Finset.sum_eq_zero_iff_of_nonneg`, `sq_nonneg`), giving each equation. Upstream
  `ZInQ.PolePolynomial.eval_polePolynomial_eq_zero_iff` does this for its MvPolynomial form; here the
  hypothesis article uses a plain `ℚ`-valued function, so ~40 lines.
- FINITE COMPUTATION: no (the `2730` factorization is `decide`). Difficulty: easy (~60 lines).

Shared design (multiplication chapter): namespace `ZInQ.Mult`, files under
`ZInQKernel/Multiplication/`. Points are `genCurve.toAffine.Point` over `K0 = QuadraticAlgebra ℚ 2 0`;
codes are `ZInQ.iota`; template relations are `ZInQ.Syntax.Rel`. Valuations on `K0` at a prime
`𝔭 : IsDedekindDomain.HeightOneSpectrum Zs` (with `Zs` the model chapter's `ℤ[√2]`) are taken as
`ℤ∪{∞}`-valued via `IsDedekindDomain.HeightOneSpectrum.valuation K0 𝔭` (multiplicative, `ℤᵐ⁰`);
a thin wrapper `ZInQ.Mult.vP 𝔭 : K0 → WithTop ℤ` is recommended. The completion is
`𝔭.adicCompletion K0`. The constants `c_*`, `ℓ_0`, `A_ht`, `T` are the syntax chapter's symbolic
`FixedExpr` values and are never evaluated (no `decide`/`norm_num` on them).
