# Height bounds in K0 (field-height-bounds)

- Lean names: `ZInQ.Mult.height_mul_le`, `ZInQ.Mult.height_add_le`, `ZInQ.Mult.height_sqrt2`,
  `ZInQ.Mult.height_eps`, `ZInQ.Mult.height_components_le`.
- Draft:
  ```lean
  theorem height_components_le (x₀ x₁ : ℚ) :
      absHeight (⟨x₀, x₁⟩ : K0) ≤ ratHeight x₀ + ratHeight x₁ + 3/2 * Real.log 2
  theorem height_eps4_mul_le (x : K0) : absHeight (eps ^ 4 * x) ≤ absHeight x + 2 * Real.log (1 + √2)
  ```
- Mathlib: `Height.logHeight₁` on number fields with `instAdmissibleAbsValues`
  (Mathlib/NumberTheory/Height/NumberField.lean) is NOT normalized by the degree: for `K0`,
  `absHeight = logHeight₁ / 2` and `totalWeight K0 = 2`. Use `logHeight₁_mul_le`, `logHeight₁_add_le`,
  `logHeight₁_pow`. The model chapter's `h` (x-height article) must be identified with
  `logHeight₁ / 2`; coordinate with the model chapter's implementation (it may define its own
  height via the fraction formula; then prove (1)-(2) from the x-height-formula article instead).
  `K0` needs a `NumberField` instance: `#synth NumberField (QuadraticAlgebra ℚ 2 0)` fails with
  plain `import Mathlib` (verified with `lake env lean`); provide it from the field instance given
  by `Fact (¬ IsSquare (2 : ℚ))` (Hypotheses/MordellWeil.lean), `CharZero` and `Module.Finite ℚ`.
- FINITE COMPUTATION: no (`h(s)`, `h(ε)` are exact computations through the fraction formula:
  `s = s/1`, `N(s) = -2`; `ε` unit). Difficulty: medium (~200 lines, mostly API alignment).

Shared design (multiplication chapter): namespace `ZInQ.Mult`, files under
`ZInQKernel/Multiplication/`. Points are `genCurve.toAffine.Point` over `K0 = QuadraticAlgebra ℚ 2 0`;
codes are `ZInQ.iota`; template relations are `ZInQ.Syntax.Rel`. Valuations on `K0` at a prime
`𝔭 : IsDedekindDomain.HeightOneSpectrum Zs` (with `Zs` the model chapter's `ℤ[√2]`) are taken as
`ℤ∪{∞}`-valued via `IsDedekindDomain.HeightOneSpectrum.valuation K0 𝔭` (multiplicative, `ℤᵐ⁰`);
a thin wrapper `ZInQ.Mult.vP 𝔭 : K0 → WithTop ℤ` is recommended. The completion is
`𝔭.adicCompletion K0`. The constants `c_*`, `ℓ_0`, `A_ht`, `T` are the syntax chapter's symbolic
`FixedExpr` values and are never evaluated (no `decide`/`norm_num` on them).
