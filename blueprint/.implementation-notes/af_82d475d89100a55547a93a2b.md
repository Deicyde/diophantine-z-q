# Implementation note: The literal cutoff

- Lean name: `ZInQ.Size.literal_cutoff`.
- Draft:
  ```lean
  theorem literal_cutoff (hCAT : CatalogueBound) :
      Syntax.R = Syntax.D ∧
      Syntax.T = (96 * 10 ^ 13) ^ 13 * Syntax.D ^ (2210 * Syntax.G0 ^ 2 * Syntax.D ^ 3) ∧
      Syntax.T < 2 ^ 2 ^ 2 ^ 9013
  theorem formal_multiple_succeeds (hNs : 1 ≤ Syntax.Ns) :
      1 ≤ Syntax.M0 ∧ Syntax.M0 ≤ Syntax.Ns ^ 10 ∧ Syntax.IsFormalMultiple Syntax.Ns Syntax.M0
  ```
  Interface for other chapters: the multiplication chapter uses `formal_multiple_succeeds`
  (CAT enters only through `hNs`, supplied by `(Ns_lt hCAT).1`, or without CAT from Dirichlet's
  theorem `Nat.infinite_setOfPred_prime_and_eq_mod`; see the formal-multiple-size note) and possibly `T_eq`; the assembly chapter uses `R_eq_D` to match `Aht` with
  `heightH6` of hypothesis H (`ZInQ.heightH6`, ZInQKernel/Hypotheses/Height.lean). Note that
  `heightQ` there is real-valued (`R ^ (R * E0)` with `Real.rpow`), while `Syntax.Q` is natural:
  a cast lemma `((Syntax.Q : ℕ) : ℝ) = heightQ Syntax.D` (via `Real.rpow_natCast`) belongs with
  whoever matches `Aht` with `heightH6`.
- Proof: `R_eq_D`, `T_eq`, `closedT_lt`, `leastFormalMultiple_bounds`, `leastFormalMultiple_spec`.
- Mathlib: none directly.
- Finite computation: no.
- Upstream reuse: `ZInQ.ExplicitCutoffBounds.t_lt_triplePower` through `closedT_lt`.
- Difficulty: low (assembly of the leaves).

Shared design (majorant notes): `Maj B h P : Prop := if h = 0 then P.totalDegree ≤ 1 ∧ l1 P ≤ 1
else P.totalDegree ≤ B ^ (8 * h) ∧ l1 P ≤ 2 ^ B ^ (8 * h)` (helper def in `ZInQKernel/Size/Majorant.lean`).
Heights are computed on the syntax chapter's node lists (`ZInQ.Syntax.Template.nodes`, produced by
`Prog.dag`), so they depend only on syntax, never on the values of fixed expressions.
