# Implementation note: Capped arithmetic

- Lean names: reuse upstream `ZInQ.PrecisionArithmetic.saturate` and its lemmas; add
  `ZInQ.Machine.saturate_factorial` and the expression-level lemma
  `ZInQ.Machine.cappedEval_eq_saturate` for a small expression syntax (`lit`, `add`, `mul`,
  `pow`, `max`, `fact`).
- Upstream reuse (lean/ZInQ/PrecisionArithmetic.lean, PrecisionAlgorithms.lean): `saturate`,
  `saturate_add`, `saturate_mul`, `saturate_max`, `saturate_pow`,
  `saturate_pow_saturate_exponent`, `saturate_pow_saturate`, `saturate_le_iff`,
  `four_mul_pow_lt_iff`, `mul_lt_iff_le_div_pred`, `cappedMul_eq_saturate`,
  `cappedPower_eq_saturate`, `cappedPower_le_iff`, `checkedCappedPower_zero_cap`. Items 1, 2, 4
  and the threshold are already proved there.
- Draft (new part):
  ```lean
  theorem saturate_factorial (L k : ℕ) : saturate L k.factorial = cappedFactorial L k
  theorem cappedEval_eq_saturate (L : ℕ) (e : CapExpr) : cappedEval L e = saturate L e.val
  ```
- `saturate_pow_saturate_exponent` and `saturate_pow_saturate` assume `1 ≤ L`; the threshold
  statement also covers `L = 0` (both sides false), which the precision test can reach, so
  prove that case separately (`checkedCappedPower_zero_cap` is the matching upstream lemma).
- Mathlib: `Nat.factorial`, `Nat.factorial_succ`.
- FINITE COMPUTATION: no.
- Difficulty: low (~80 lines new).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
