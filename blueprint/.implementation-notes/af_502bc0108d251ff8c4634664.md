# Implementation note: Size of N_s and ell

- Lean name: `ZInQ.Size.Ns_lt`, `ZInQ.Size.ell_lt`.
- Draft:
  ```lean
  theorem Ns_lt (hCAT : CatalogueBound) : 1 ≤ Syntax.Ns ∧ Syntax.Ns < 2 ^ 2 ^ 2054
  theorem ell_lt (hCAT : CatalogueBound) : Syntax.ell < 2 ^ 2 ^ 2063
  ```
- Proof: `Ns = Ps * Hcat ≤ 2^433 * 2^(22 * W^4)` (`(2^(W^3))^(22W) = 2^(22 W^4)` by
  `← pow_mul` and `ring_nf` on exponents), then `Nat.pow_lt_pow_right` with the exponent
  inequality `433 + 22 * W^4 < 2^2054` from `W < 2^512` (`Nat.pow_lt_pow_left`), proved with
  `omega`-free `calc` steps on symbolic `W` (do not `decide` with `W` unfolded: `W^4` has 1740
  bits, which is fine, but keep it symbolic for uniformity; `decide` on `22 * (2^512)^4 + 433 <
  2^2054` is a cheap closed literal check if convenient). Same for `ell` with exponent
  `4 + 433*2916 + 16104 * W^4 < 2^2063`.
- Mathlib: `Nat.pow_lt_pow_left`, `Nat.pow_lt_pow_right`, `Nat.pow_le_pow_left`, `pow_mul`,
  `Nat.mul_lt_mul_of_lt_of_lt`.
- Finite computation: only closed literal comparisons such as `22 * 2^2048 + 433 < 2^2054`
  (kernel `decide`).
- Upstream reuse: none.
- Difficulty: low (~60 lines).

Shared design (size notes): namespace `ZInQ.Size`, files under `ZInQKernel/Size/`. Constants are
the syntax chapter's abbreviations `ZInQ.Syntax.Ps`, `W`, `Hcat`, `Hmax`, `Ns`, `M0`, `cstar`,
`ell`, `F`, `D`, `G0`, `E0`, `R`, `Q`, `Bcm`, `Ccm`, `Aht`, `T` (natural numbers or `toNat` of
`FixedExpr.val`; prove unfolding lemmas `T_def : T = (48 * Aht)^13` etc. by `rfl`/`simp
[FixedExpr.val]`). None of them is ever evaluated: never `decide`, `norm_num` or `rfl`-reduce a
goal containing `D`, `T`, `Hcat`, `M0`, `cstar`, `ell` or `c_3`; mark them `@[irreducible]`
after the unfolding lemmas, and work with `Nat.pow_lt_pow_left/right`, `Nat.pow_le_pow_left/right`,
`Nat.lt_two_pow_self`, `Nat.mul_lt_mul_of_lt_of_lt` as in upstream
`ZInQ.ExplicitCutoffBounds` (lean/ZInQ/ExplicitCutoffBounds.lean).
