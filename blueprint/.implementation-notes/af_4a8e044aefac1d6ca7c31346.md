# Implementation note: Size of the program literal

- Lean names: `ZInQ.Machine.wrapperPrec_size` (finite part), `ZInQ.Machine.code_lt` (general
  bound, belongs with the decoding lemma), `ZInQ.Machine.c3_lt`.
- FINITE COMPUTATION (the size of the constructed instruction list). Decidable form:
  ```lean
  theorem wrapperPrec_size :
      (wrapper precisionMachine).length ≤ 2 ^ 20 ∧
      ∀ ins ∈ wrapper precisionMachine, ins.maxIndex < 2 ^ 20
  theorem code_lt (Π : Prog) : code Π < 2 ^ (encBits Π * (4 * Π.length + 1) + 1)
  theorem c3_lt : c3 < 2 ^ (2 ^ 27)   -- from the two above; `c3` itself is never evaluated
  ```
  Here `encBits Π` is the `w` of the encoding and `Instr.maxIndex` is the maximum of the
  register index and the targets.
- Checking method. Milestone 1: `native_decide` on the list (about 147,000 instructions for
  upstream's machine). Milestone 2: either kernel `decide` (feasible only if the lowering reduces
  efficiently in the kernel; untested) or, preferably, a structural bound proved by induction on
  the structured program: `(lower S).length ≤ k * size S + c` and all indices bounded by the
  register count and the layout length, together with a small count of the statements of the
  precision program. The bound `2^20` leaves room over upstream's `146,780` instructions and
  maximum index `146,779` (decoded from the saved literal: `w = 18`, 10,568,107 bits).
- Consumer: the size chapter's bound "every literal fixed constant is at most `T`" for
  `integer_constant_3 = c3`; `c3 < 2^(2^27) ≤ T` follows there symbolically from
  `log₂ T ≥ log₂ D > 256 · (324!)^4`.
- Mathlib: `List.length`, `Nat.pow_le_pow_right`, `Nat.lt_pow_self`.
- Upstream reuse: none.
- Difficulty: low given the program terms (~60 lines plus the check).
