# Implementation note: Nonzero multiples of the generator are nondegenerate

- Lean name: `ZInQ.Machine.nondegenerate_zsmul_genP0`.
- Draft:
  ```lean
  theorem nondegenerate_zsmul_genP0 {m : ℤ} (hm : m ≠ 0) : Nondegenerate (m • genP0)
  theorem accepts_cond2_of_cond1 ... -- condition 1 ⇒ condition 2
  ```
- Proof: the torsion theorem of the model chapter (`torsion_eq_two_torsion`), `genP0 ∉ E[2]`
  (ordinate nonzero, `decide`-level arithmetic in `K0`), `addOrderOf`/`IsOfFinAddOrder` API;
  a point with `y = 0` satisfies `2 • Q = 0` (Mathlib's affine doubling: `Point.neg` of
  `.some x 0` is itself).
- Mathlib: `WeierstrassCurve.Affine.Point.neg_some`, `IsOfFinAddOrder`, `addOrderOf_dvd_iff_zsmul_eq_zero`.
- Upstream reuse: none.
- FINITE COMPUTATION: no (the torsion theorem's point counts are finite checks of the model chapter).
- Difficulty: low (~60 lines).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
