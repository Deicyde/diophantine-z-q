# Implementation note: The precision program computes the precision predicate

- Lean name: `ZInQ.Machine.precisionStmt_correct`.
- Draft:
  ```lean
  theorem precisionStmt_total (c : Fin 5 → ℕ) : ∃ o, Exec precisionStmt (init (List.ofFn c)).reg o
  theorem precisionStmt_correct (c : Fin 5 → ℕ) : precisionStmt.Accepts (List.ofFn c) ↔ acceptsNaturals c
  ```
- Proof: one lemma per macro layer (signed arithmetic, `ZS` arithmetic and norm, fractions),
  the binary-scalar-multiplication loop invariant (`acc + k • base = m • P0` on represented
  points, `k` halving), `jacDouble_spec`/`jacAdd_spec`, the guard lemma via
  `intPair_norm_eq_zero`, and `cappedEval_eq_saturate` + `four_mul_pow_lt_iff` for the second
  test. Split into PRs: (i) macro layers, (ii) scalar multiplication, (iii) exact values and
  first test, (iv) second test, (v) assembly.
- Mathlib: `zsmul` on `WeierstrassCurve.Affine.Point`, `Int.natAbs`, `Rat` arithmetic.
- Upstream reuse: `ZInQ.PrecisionArithmetic.*`, `ZInQ.PrecisionAlgorithms.*`.
- FINITE COMPUTATION: no.
- Difficulty: high (~800 lines over several PRs).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
