# Implementation note: The precision program

- Lean name: `ZInQ.Machine.precisionStmt : Stmt`, with macro layers `ZInQ.Machine.SInt`
  (normalized signed pairs in two registers), `ZInQ.Machine.ZS` (pairs of signed integers),
  `ZInQ.Machine.Frac`, and subprograms `scalarMul`, `jacAddStmt`, `jacDoubleStmt`,
  `cappedAht`, `precisionLoop`.
- Design note: S22 (`precision-register.js`) is not in this repository, so the Lean program is
  written afresh following the article; `c_3` then differs from the saved literal (affects only
  the external cross-check, not the witness count or the proof).
- The fixed expression of `A_ht^(0)` is given as a `CapExpr` term
  (`2 * 10^13 * max 1 (max Ccm (D ^ (17 * D * E0)))` with `D = 324! * 3 ^ (256 * (324!)^4)`, ...)
  and evaluated only by `cappedEval L`.
- Mathlib: none.
- Upstream reuse: `ZInQ.PrecisionAlgorithms.cappedMul`, `cappedPower` (the register program
  mirrors these loops).
- FINITE COMPUTATION: no.
- Difficulty: medium-high (~400 lines of program text and macro specs).

Shared design (machine notes): namespace `ZInQ.Machine`, files under
`ZInQKernel/Compiler/Machine/`. Primitive programs as `Array Instr`, configurations
`ℕ × (ℕ →₀ ℕ)` or `ℕ × List ℕ`, one-step function `step : Prog → Config → Option Config`
so that Mathlib's `StateTransition.eval`/`Reaches`/`Respects`/`tr_eval`
(Mathlib/Computability/StateTransition.lean) give runs and simulations. Large programs (the
interpreter, the precision machine, the wrapper) are Lean terms built by functions; their
codes, in particular `c_3`, are never evaluated by any proof.
