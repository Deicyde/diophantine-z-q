# Replaying historical review tools

The historical review records are preserved at [review-archive-v17](https://github.com/elliotglazer/diophantine-z-q/tree/review-archive-v17), commit `005b17abfbefd8bee7b34f3bbe8f5aabf872eb1f`. The [distillation](distilled/) summarizes them. Archiving a record does not resolve a mathematical finding or renew an old acceptance.

Historical preparation, review, and release scripts are retained as source code. Their old working-directory invocations are retired from the current checkout when their review inputs are archived. To inspect or attempt to reproduce their original work, use a separate checkout of the archive:

```sh
git fetch origin tag review-archive-v17
git worktree add --detach ../diophantine-review-archive 005b17abfbefd8bee7b34f3bbe8f5aabf872eb1f
cd ../diophantine-review-archive
```

Then follow the tool's original instructions there. Some preparation scripts refer to the original authors' work directories, credentials, or software installations. Preserving them does not make those external inputs available or certify that every historical command is portable. Do not run an old publishing or deployment command simply to inspect its records.

This retirement applies to the historical evidence-preparation and review tools whose data are archived from `research/version14/evidence`, `research/version14/proofs`, `research/version15/snapshots`, `research/version15/evidence`, `research/version15/protocol`, `research/version15/history`, the former quartic214 review trees, and the historical review folders under `docs`. It does not retire the current computation checks, kernel audit, current manuscript build, or their retained inputs. Those continue to run from the current checkout.

Frozen manifests and old handoff plans keep their original hashes and paths. Read them against their recorded source revision; when a tool takes an explicit source-tree argument, supply that revision rather than the current checkout. The archive tag preserves the Git history containing those revisions. A historic manifest is not a checksum inventory for the current checkout. Resolve an old alias together with its recorded SHA256: paths were reused, so a same-named current file with a different hash is not the referenced object. Bare hashes can likewise identify an archived copy of the recorded bytes.

The maps in `archive-batches/` describe the records retained when each batch was prepared. Later batches may archive some of those records too. Resolve their historical paths against the same archive commit; an earlier map is not a promise that those records will remain in the current tree indefinitely.

In particular, `research/version15/ACTIVE-REVIEW-RESOLUTION.json` records the old review overlay. Its `base_commit` entries identify historical Git objects; its relative `overlay_path` entries belong to the archived Version15 directory. `research/version15/CANDIDATE-MANIFEST.json` describes an old consolidated candidate, not the current repository tree. `research/version14/selection/annex-r2/EXCLUSIONS.json` is a selection ledger for an earlier source workspace, not a list of files required in the current checkout. These files retain their original wording, hashes and paths. Words such as "active" and "current" in them refer to their historical preparation state. The archive preserves the records that were committed; it does not supply uncommitted external workspace files named by an old ledger.

Current package guides link directly to the archived record when its local copy has been removed. Released TeX and PDF files remain byte-identical; historical paths printed inside them should likewise be resolved against their recorded revision or the archive tag.

The retained current inputs include the kernel contract and all its pinned files, the current quartic verification packages, the manuscript assembly sources, and the active audit-history checker's records. The 222-variable verifier's source-copy inventory includes review-named files; those remain because it actually hashes them. `research/quartic214-manuscript-review/FOUNDATION_TRANSITION.md` remains because the manuscript assembler actually renders it.

`research/quartic214/check_port.py` also hashes the exact `public_source` files named by `research/quartic214/sources/public-provider-scopes.json`. Those source files remain at their original paths with their original bytes. Its check does not recursively open every historical path printed inside those records. Such historical references retain their original meaning and resolve through the archive, rather than becoming new current-checkout requirements. The same distinction applies to old overlay, selection and installation inventories: their contents describe the recorded historical tree, while any input that a current check actually opens stays in the current tree.
