   analytic `G` with `G(2 − s) = G(s)` near `1` has no simple zero at `1`.
3. **TYZ's `𝓛²` as printed** (`lcalSqPrinted R n`): `0` if `ord_{s=1} > 1`; `L(E_n,1)/(2^{2k−3}Ω_n)` if

## 2. The functional equation with root number `+1` (how)

This is the same route as the tree's `functionalEquation5_of_deuring_fourier` (`Contrib/HeckeFE/Basic.lean`), with
two changes.

* **Coefficients, every odd squarefree `d`** (`lseries_eq_twistedL`): `L(C_d, s) = T_c(s)` with
  `c = ¼ c_d`, `c_d(α) = (N α / d) u(α)`, on `Re s > 3/2`. The ingredients are:
  * Deuring at `d = 1` (`deuringCd_of_gaussPointCount` with `GaussFE.gaussPointCount`);
  * the twist `cdCoeff d n = (d/n) cdCoeff 1 n` (`HeckeAll.cdCoeff_twist`);
  * reciprocity `(d / N α) = (N α / d)` on norm fibres (`jacobi_unit_swap`), which holds because `u(α) ≠ 0`
    forces `N α ≡ 1 (mod 4)` (checked by `decide` on `(ℤ/4)²`).

  The tree's `DeuringCd d` was available only for `d ≡ 1 (mod 4)`.
* **Fourier relation for `d ≡ 3 (mod 4)`** (`fourierHat_cd_eq3`, `cdFourier3_of_oddGauss`). This adapts the tree's
  `fourierHat_cd_eq`. `d·a ≡ −a (mod 4)` and `u(−α) = −u(α)` (`decide`), so `ĉ_d = −(2-part)(odd part)` and
  `κ = −4d(1+i)(2/d)`. The odd Gauss sums hold for every odd squarefree `d` (`oddGauss_of_prime`, `oddGauss_prime`).
* **Sign.** For `d ≡ 1 (mod 8)`, `(2/d) = 1`; for `d ≡ 3 (mod 8)`, `−(2/d) = 1`. In both cases `κ = 4d(1+i)` and
  `−iκ(1+i) = +8d` (`fourierRel_plus`). With the tree's `lambdaC_two_sub` and `const_identity`, negated, this gives
  `Λ(2 − s) = Λ(s)`.

Remark (not done): `fourierHat_cd_eq3` also gives `κ = −4d(1+i)` for `d ≡ 7 (mod 8)`, hence root number `−1` there.
`d ≡ 5` is already in the tree. The only missing piece for `d ≡ 7` would be the analogue of `FunctionalEquation5`.

## 3. The definition of TYZ's `𝓛` that is formalized (read with care)

The TYZ source is **not on this host** (`~/tyz-src` is absent). The definition is taken from the project's
transcriptions of L338–353:
* `scratch/rv-tyz-inputs/tyzcalc.py`, header: ord 0 and ord 1 formulas, `R_d` = 2 × Néron–Tate height of a generator;
* `docs/research/h33-sign.md`, table rows L338–351;
* `rv-tyz-inputs.md` §1.7: "`𝓛(n) = 0` exactly when `ord_{s=1} > 1`".

So the definition's wording is UNVERIFIED by this task. Conventions:

* `k = #{p ∣ n}`, `a = 1` (odd `n`), hence `2^{2k−2−a} = 2^{2k−3}`. `lcalSqPrinted` is meant for odd `n` only, which
  are all the classes the consumer uses.
* `L(E_n, s)` is Mathlib's `L(C_n, s)`: `E_n : ny² = x³ − x` is `ℚ`-isomorphic to `C_n` (rv-pn-encoding, lfun-cd).
  `F` is its entire continuation, chosen as in the tree's `lValOne` and unique by `IsLContinuation.eq`.
* `Ω_n = omegaTYZ n = (2/√n)∫₁^∞ dx/√(x³ − x)`, as in `lcalSq`. `L′(E_n, 1)` is `deriv F 1`.
* **The regulator** `R_n` (twice the Néron–Tate height of a generator in rank one) is a parameter `R : ℕ → ℝ`. The
  restated hypotheses quantify over every `R`. This is harmless: the `ord = 1` branch never fires on the classes
  `1, 3`, so `lcalSqPrinted R m` does not depend on `R` there (`lcalSqPrinted_eq`). The `∀ R` form is therefore
  equivalent to the instance at TYZ's true regulator, and to the instance at any one `R`.

  A concrete regulator could be built from Tau Ceti's `Point.canonicalHeight`, vendored in
  `Contrib/TauCeti/.../CanonicalHeight`. It is not used, because its normalization (`log` vs `½ log`) would need
  reading, and it would only enter a dead branch.
* If L338–345 instead split by class (`𝓛² = L(E,1)/…` for `n ≡ 1, 2, 3`, `0` when `ord > 1`), then `lcalSq = 𝓛²` holds
  without any root number, because `L(E_m, 1) = 0` whenever `ord ≥ 1`. The ord-split reading formalized here is the
  one that needs root number `+1`, which is what the verdict asks for.
