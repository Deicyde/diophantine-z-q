# Appendix F: the old level and the actual coefficient support

**Scoped stop: the existing inertia support cannot contain a coefficient sieve prime that is `T.Good`.** `InertiaOn` uses the support detected by the type character. Its caller cannot enlarge that set to the actual coefficient support when a late sieve is prime to the type modulus. The checkout already puts the moving theta prime in the concrete odd type modulus; it does not connect every late sieve of the same lifted source to that modulus. The existing `hexcl` and `good_hecke` interfaces also lack the coefficient support exclusion. Following the stop rule, this run adds no Lean declarations or prints. This is a mismatch in the formal interfaces; no manuscript or printed-source error was established.

The existing theorem `ThetaCoeff.no_good_mem_stationary` (`ZInQKernel/Contrib/OneProof/RC/ThetaCoeff/Model.lean:27`) proves that `IsTypeChar T χ`, the chosen good Frobenius elements, and `TypeDetectsRadicals χ support` imply `∀ q, T.Good q → q ∉ support`. For a set `Scoeff` of primes, the inclusion `Scoeff ⊆ support` holds exactly when `Scoeff ⊆ T.m.primeFactors`. These deductions are on-the-spot (c) from the existing theorem and the definitions. The stage join still has to identify `D.ℓ₀ θ` with the prime `S.ℓ₀` of the actual theta lift. `LabelData` documents the intended choice that `m₁` includes the sieve primes (lines 69–82), but its fields do not list the actual late sieves or assert their divisibility into `m₁`. A stage presentation that actually covers all sieve primes can therefore use the existing constructor with a matching type and character. The missing comparison is with the sieves defining this source; neither coverage nor failure of coverage for a particular late prime is asserted by the base.

There is a second obstruction if a sieve prime remains `T.Good`. `FourierData.FormwiseHecke` (`ZInQKernel/Contrib/OneProof/RC/O12/Fourier.lean:44`) asks for the formula for all `T.Good q` outside `U`. `formwiseHecke_of_ambient` (`ZInQKernel/Contrib/OneProof/RC/O12/Build.lean:34`) takes `hexcl` on the same domain intersected with `avoid`; `thetaData` stores the result as `good_hecke` (`ZInQKernel/Contrib/OneProof/RC/O12Theta/Inputs.lean:125` and `:147`). An old-level prime still in `T.Good` must be in `avoid` for a valid ambient level test, so the ambient branch cannot prove the comparison there. The restricted Fourier proof would provide no result at that prime. If the same stage type is proved to cover `Scoeff`, `T.Good q` supplies `q ∉ Scoeff` at both callers, with no change to their statements. If `T.Good` is kept broader, a restricted Hecke theorem would need its exclusion passed through the consumers, and the Kummer step would still need a proof that the type and added bits detect all quadratic characters of the trace quotient. Restricting the Hecke domain alone cannot prove that detection claim.

These are on-the-spot (c) domain calculations. The same construction could then retain the restricted old-level field from the start. Neither the stage type comparison nor the old level can be chosen independently of the actual lifted source.

## Known issues

- `BlockLevels.old_good` and `LevelSetup.old_good` demand coprimality at every `T.Good` prime even when the chosen old level has a `T.Good` sieve divisor. Such a divisor makes these fields impossible. A proof of full type coverage could instead remove the conflict for the concrete stage, but the generic fields do not express the manuscript's domain.
- `O12/Fourier.lean` describes fixed and moving exclusions in the comment above `FormwiseHecke`; its body implements them only to the extent that they are already excluded by `T.Good`. `O12Theta.thetaData` separately assumes `∀ p, T.Good p → S.Good p`, which is not a theorem about the actual lift's late sieve list.
- The old weighted transformation is still the first analytic stop of `docs/research/rc-blocks-per-u.md`; this interface finding does not discharge it. No source locator was supplied from memory.
