The new leaf is weaker than the field. It assumes `X` projective (a closed immersion into `ℙ^N_K`), geometrically
integral, geometrically normal and with a `K`-point, and it quantifies over representations on locally Noetherian test
schemes. The field assumed only "proper and geometrically normal". So no term of the field's type can be built from
the leaf, and `autofold.py` does not apply.

* the generation conversion `OpenAddedLeaves25 → 24 → 23 → 22PZ`, where `picZeroAbVar :=
  PicZeroChar0.picZeroAbVar0_of_leaves … n.kleimanPicZeroProper`;

  conversion), through `HodgeTateFromPairing.hodgeTateDecompAbVar_of_open`, which also uses the field only through
  `picZeroAbVar0_of_leaves`.

So the chain reads the field only as `PicZeroChar0.PicZeroAbVar0`, and `KleimanSection2.picZeroAbVar0_of_954` proves
that from the new leaf. kleiman-section2's draft `TailZ56` was written against TailZ55. It did not cover the second
reader, which fold34-ht added later.
